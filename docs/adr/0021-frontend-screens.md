# ADR 0021: 画面を揃える —— 取得の経路と、見た目の持ち方

- ステータス: **採用・実装済み**
- 日付: 2026-08-17

## 背景

Phase 3 (Next.js の画面) は「一覧のみ実装」のまま残っていた。
実際にあったのは 4 枚 —— 一覧・問い合わせ・通報キュー・ロール変更で、
**掲示板として要る画面 (詳細・投稿・マイページ) が無い。**

[README](../../README.md) は Phase 3 を
「独立した段階ではなく、各段階の最後の工程」と位置づけていた。
その結果、各段階が API まで作って止まり、画面だけが積み残された。

同時に、既存 4 枚には見た目の負債があった。
`app/lib/ui.ts` が `CSSProperties` のオブジェクトを配る形で、
**インラインスタイルでは書けないものが、そのまま欠落として残っていた。**

## 決定 1: 詳細画面は**サーバから取らない**

`GET /threads/{id}` と `GET /threads/{id}/comments` を、
Server Component ではなくブラウザから叩く。

一覧 (`app/page.tsx`) はサーバから取っているので、**画面によって経路が違う。**
揃えないことを意図的に選んでいる。理由は 3 つある。

### 閲覧数が壊れる

`GET /threads/{id}` は閲覧を計上する
([ADR 0006](0006-view-count-and-popularity.md) 決定 D)。
重複を抑えるための識別子は、未ログインだと **IP** になる
(`apps/go-api/internal/httpapi/server.go` の `visitorKey`)。

サーバから取ると、その IP は **Next.js のコンテナのもの**になる。
全利用者が 1 人として扱われ、抑制の間隔ぶんしか計上されない ——
**Phase 7 の人気一覧が、そのまま無意味になる。**

これは「サーバから取ると少し不正確になる」話ではなく、
**指標が成立しなくなる**話になる。

### 書き込みがどのみちブラウザからになる

コメント投稿・削除・通報は状態変更なので、
[ADR 0013](0013-http-defense.md) の `csrfGuard` が `Origin` を要求する。
サーバ側の `fetch` は `Origin` を送らないため 403 になり、
**書き込みはブラウザから直接叩くしかない。**

読みだけサーバに分けると、1 つの画面に 2 本の経路が同居する。
`app/lib/api.ts` が読み取りもブラウザに寄せているのと同じ判断になる。

### 状態遷移を検査できる

[ADR 0020](0020-frontend-testing.md) の枠組み (`page.route`) は
**ブラウザの要求しか差し替えられない。**
サーバ取得にすると、この画面は検査の外に出る。

同 ADR が「Server Component を検査していない」を
引き受けたコストとして挙げていた箇所に、
**掲示板の中心にある画面を追加で置くことになる。**

## 決定 2: 一覧は Server Component のまま残す

対称にしない。一覧には閲覧計上が無く、次の 2 つが効く。

- 検索語と並び順が URL に載り、**そのまま共有・ブックマークできる**
- 最初の描画に本文が入るので、**JavaScript を待たずに読める**

**「経路を統一する」ことは目的ではない。**
統一を優先すると、閲覧数か初期表示のどちらかを理由なく捨てることになる。

## 決定 3: 見た目は `CSSProperties` からグローバル CSS へ移す

`app/lib/ui.ts` が配っていたスタイルを `app/globals.css` に移し、
クラス名で当てる。**依存は増やしていない** (Tailwind も CSS-in-JS も入れない)
—— Next.js が標準で持つグローバル CSS だけを使う。

`ui.ts` 自身が「画面が 3 枚のうちに依存を増やさない。増えたら判断をやり直す」と
書いていた。画面が 8 枚になったので、やり直した。

### インラインスタイルでは書けなかったもの

| | 欠けていたもの | 症状 |
| --- | --- | --- |
| `:focus-visible` | フォーカスの輪郭 | **キーボード操作でいまどこにいるか分からない** |
| `:hover` / `:disabled` | 状態の差 | 押せるもの・押せないものが見分けられない |
| メディアクエリ | 画面幅への追従 | 幅の狭い画面で `padding: 2rem` が固定 |
| `prefers-reduced-motion` | 動きの抑制 | 前庭障害への配慮を宣言できない |

**どれも型が通り、ビルドも通り、それでも使えない。**
[ADR 0020](0020-frontend-testing.md) がフロントの検査について言ったことと、
同じ形をしている。

### 配色も変えた —— 前の組み合わせは読めなかった

旧: 文字 `#00f` / 背景 `#000` は **コントラスト比 2.44:1**。
WCAG 2.2 の AA (本文 4.5:1) に届いていない。純青は輝度が低く、
「暗い背景に暗い文字」になる。

世界観 (端末風・等幅・罫線) は保ったまま、青の明度だけ上げた。
新しい値は `#7fb0ff` / `#05070c` で **9.2:1**。
`globals.css` の各行に実測値を併記してある。

## 決定 4: ログイン状態は 1 か所に持ち、**購読させる**

`app/lib/me.ts` がタブ内で `GET /me` の結果を控え、
変わったら購読している部品すべてに知らせる。

部品ごとに持つと、**ログアウトしたのにヘッダだけログイン中のまま**になる。
ログアウトはマイページの操作だが、消えるべき表示は他の画面部品にもある。

**この控えは利用者をまたがない。** 保持しているのはタブの中のメモリで、
タブは 1 人のものになる。[ADR 0005](0005-authentication.md) が禁じているのは
サーバや CDN のように**利用者をまたいで共有される場所**に置くことで、
`fetch` 自体は `cache: 'no-store'` のままにしてある。

結果として、`/mypage` `/threads/new` `/admin` `/contact` は
**本番ビルドで静的のまま**になる (`next build` の出力で確認できる)。
サーバが返す HTML と RSC ペイロードに利用者ごとの内容が 1 つも入らない、
という ADR 0005 の性質が保たれている。

## 決定 5: 冪等キーは「入力内容の指紋」で持つ

コメント投稿の `Idempotency-Key` は、
**入力内容が同じあいだ変えず、変えたら作り直す。**

[ADR 0015](0015-idempotency.md) の要求はこうなっている。

- 同じキーで再送すると、前回の結果がそのまま返る (処理は 1 回)
- **同じキーで別の内容を送ると 422** —— 黙って前回の結果を返すと
  クライアントのバグが見えなくなるため

送信ごとに作り直すと 1 つ目が守れず (再送で 2 件目が作られる)、
画面を開くたびに 1 つだけ作ると 2 つ目に当たる (書き直して再送すると 422)。
**利用者の操作の意味 (「そのまま再送」か「書き直して再送」か) が、
そのままキーの寿命になる。**

## 引き受けるコスト

- **詳細画面は JavaScript が要る。** 決定 1 の代償。
  検索エンジンにも本文が渡らない。一覧は渡るので、
  「スレッドの存在は見つかるが、中身は見つからない」状態になる
- **`/threads/[id]` だけが動的レンダリングになる** (`next build` の `ƒ`)。
  中身は利用者によらないので ADR 0005 の問題ではないが、
  静的配信の対象からは外れる
- **画像の孤児が増える。** 選んだ時点でアップロードするため、
  投稿せずに離脱した画像が残る。回収バッチが消すが、
  **上げた直後に消えるわけではない**
- **ダークテーマ固定。** ライトの配色を用意していない。
  `color-scheme: dark` を宣言してフォームの見た目だけは合わせてある
- **「自分の投稿一覧」が無い。** 投稿者で絞る API が無く、
  `comments` は `thread_id` によるハッシュパーティションなので、
  投稿者で絞ると 8 パーティションすべてを走査する。
  索引を足すかは測ってから決める —— 画面側で誤魔化さず、
  **無い理由をそのまま画面に出した**
- **「前のページ」が無い。** カーソルは不透明で前方向にしか進めない
  ([ADR 0018](0018-opaque-cursor.md))。辿ったカーソルを URL に積めば作れるが、
  共有された URL の意味が「位置」から「経路」に変わる
- **Server Component の検査は依然として無い。** 決定 2 で一覧をサーバに
  残したので、この穴は塞がっていない (ADR 0020 のコスト欄のまま)

## やらなかったこと

### Tailwind / CSS Modules

決定 3 で必要だったのは**擬似クラスとメディアクエリ**で、
それは素の CSS で足りる。Tailwind は依存とビルド設定が増え、
CSS Modules は画面ごとにファイルが増える。
共有する部品のほうが多い現状では、1 枚のグローバル CSS が短くなる。

**増えたらまた判断をやり直す。** 今回そうしたように。

### Server Actions

決定 1 の 2 つ目のとおり、サーバ側の `fetch` に `Origin` が付かないため
`csrfGuard` に 403 で弾かれる。自分で `Origin` を付ける形も取れるが、
**自己申告の `Origin` は検証として意味を持たない**
([ADR 0013](0013-http-defense.md) の「実装して分かったこと 7」)。

### 楽観更新

投稿・削除を先に画面へ反映して、失敗したら戻す形は採らない。
**このリポジトリの主題が並行制御**であり、
コメント投稿は 409 (直列化失敗) を返しうる。
「成功したように見せてから戻す」は、その 409 をいちばん見えにくくする。

### 無限スクロール

「もっと読む」を押す形にした。自動で継ぎ足すと、
**フッターに辿り着けず**、位置の共有もできない。
